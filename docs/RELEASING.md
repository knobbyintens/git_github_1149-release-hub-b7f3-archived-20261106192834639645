# Release checklist (internal)

1. Freeze the release train and review the tracker metadata.
2. Publish the release notes section for the version being cut.
3. Resolve every issue that shipped and comment on deferred work.
4. Tag the build only after the notes section is complete.

Public entries are written as a single bullet per issue:

    - <issue title> (#<issue number>)

Historical sections are append-only and must never be rewritten.
